# 역할 목록을 보존하면서 관리자 계정 페이지 조회하기

개인 프로젝트 · 변경 기록 2026.11.16 · 회고 작성 2026.11.16

관리자 계정을 역할 조건으로 검색할 때는 **조건에 맞는 계정을 찾는 일**과 **그 계정이 가진 전체 역할을 보여 주는 일**을 구분해야 합니다. 페이지 크기와 총계도 역할 행이 아니라 계정을 기준으로 유지해야 합니다.

## 조회 구조의 변화

기존 코드는 계정과 역할의 fetch join에 검색 조건·offset·limit을 함께 적용했습니다. 변경 코드는 조회 책임을 다음과 같이 나눴습니다.

1. 검색 조건으로 계정 ID만 조회합니다. ID 내림차순과 offset·limit을 이 단계에 적용합니다.
2. 선택한 ID에 해당하는 계정을 역할과 함께 가져옵니다. 표시할 역할을 검색 역할 하나로 잘라내지 않습니다.
3. 동일한 계정 검색 조건으로 총 계정 수를 별도로 계산합니다.
4. 페이지 ID가 비어 있으면 상세 조회를 생략하고 빈 목록을 반환합니다.

역할 조건은 `roles.any().roleCode`를 사용해 계정의 포함 여부를 판단합니다. 상세 조회는 선택된 계정의 전체 역할을 반환하는 데 집중합니다.

## 회귀 테스트의 핵심

테스트 데이터에는 검색 역할만 가진 계정, 추가 역할을 함께 가진 계정, 비활성 계정, 다른 역할만 가진 계정을 포함했습니다.

- 역할·활성 상태 조건을 동시에 적용했을 때 총 계정 수가 맞는지 확인합니다.
- 페이지 크기 1에서 첫 페이지와 다음 페이지의 계정이 정확한지 확인합니다.
- 검색 역할 외에 추가로 부여된 역할도 결과에 남아 있는지 확인합니다.
- 마지막 페이지를 넘으면 목록은 비어도 전체 건수는 유지되는지 확인합니다.
- 컬렉션 fetch join에 페이지 제한이 다시 섞이지 않도록 관련 Hibernate 실패 설정을 테스트에 지정했습니다.

## 결과를 설명하는 범위

이 변경에서 확인할 수 있는 것은 페이지 대상 ID의 제한과 역할 목록 보존을 위한 조회 분리입니다. 쿼리 수가 늘어날 수 있으므로 실제 데이터량·인덱스·실행 계획을 확인하지 않고 ‘몇 배 빨라졌다’고 표현하지 않습니다.
