# 개발 기록

Java·Spring 백엔드와 Flutter 개인 프로젝트에서 마주한 문제를 **변경 이유 → 구현 판단 → 확인한 테스트 → 남은 검증** 순서로 정리합니다. Codex와 함께 개발한 결과를 검토하는 과정도 포함합니다.

이 문서는 2026년 11월 16일에 기존 Git 이력과 코드를 대조해 작성한 회고입니다. 과거에 작성한 일별 학습 일지가 아닙니다. 개인 프로젝트 기록이며 회사 운영 성과와 구분합니다.

## 먼저 읽을 두 가지

| 주제 | 핵심 판단 | 읽기 |
|---|---|---|
| JWT와 Redis 세션 | 토큰 해석과 활성 세션 검증을 분리하고, 검증 과정에서 세션을 생성하지 않기 | [인증 경계와 실패 처리](jwt-session-validation.md) |
| QueryDSL 관리자 조회 | 페이지 대상 ID를 먼저 제한하고 연관 데이터 조회를 분리하기 | [역할 목록을 보존하는 페이지 조회](querydsl-pagination.md) |

**실행 검증:** 2026.11.16 기준 인증 11개·QueryDSL 4개 테스트 통과. 고정 커밋을 분리해 실행한 [검증 기록](verification.json)을 제공합니다.

## 짧게 확인하는 순서

1. **인증 사례:** 검증 경계 → 실제 `validate` 코드 → 실패 분기와 저장 부작용 테스트를 읽습니다.
2. **조회 사례:** 계정 4개의 예시 → ID·상세·총계 조회 코드 → 역할 보존과 페이지 경계 테스트를 읽습니다.
3. 실행 환경과 통과 수는 [검증 JSON](verification.json)으로 확인합니다. 원본은 비공개 개인 프로젝트이며, 본문에는 핵심 메서드를 발췌했습니다. 공개 저장소만으로 전체 테스트를 실행할 수 있는 패키지는 아닙니다.

## AI와 함께 작업하는 방식

요구사항과 실패 조건을 먼저 문서로 정리하고, 구현·테스트 결과를 함께 검토합니다. 오류가 생기면 문서의 기준과 코드의 동작을 나눠 확인하고, 반복되는 문제는 작업 지침에 반영합니다. 글에서 **테스트 코드가 있다**는 사실과 **실제로 실행해 통과했다**는 사실을 구분합니다.
